## UX Loop Harness constraints

For requested design implementation, UI/UX review, or harness verification and repair work,
read `.harness/ux-loop/README.md` relative to the project root and load the relevant rule documents.
Apply these rules to the existing project; installation alone is not a request to scaffold or migrate it.
For unrelated tasks, do not start a UX workflow. If multiple agent instruction files contain this
entry point, apply the rules once.

These are portable constraints, not an executable runner. Use the project's actual tools and report
missing capabilities accurately. Preserve existing project instructions and explicit user choices;
this dock does not grant new authority or require repeating approvals already given.
Keep project-specific customizations outside OpenDock-managed blocks.
