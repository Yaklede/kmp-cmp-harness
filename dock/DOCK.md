# UX Loop Harness

**디자인을 구현하고 검증하는 AI 작업에 적용하는 제약조건 패키지입니다.**
기존 프로젝트에 추가해 사용합니다. 새로운 앱이나 KMP/CMP 프로젝트를 생성하지 않습니다.
웹·네이티브·크로스플랫폼 프로젝트에 공통 규칙을 적용하고, KMP/CMP 규칙은 해당 기술을 쓸 때만 읽습니다.

## 포함된 규칙

- 기존 구조, 도구, 사용자 지침과 승인 범위를 먼저 확인합니다.
- 디자인에서 관찰한 사실, 추론, 미확정 정책을 구분합니다.
- 디자인 의도를 보존하며 누락된 UX 상태와 접근성을 검토합니다.
- 로직 검사, 실제 UI 입력, 플랫폼 검사, 사람의 판단을 구분합니다.
- 변경된 소스에 맞는 증거로 판정하고, 실패 원인을 좁혀 제한된 수정 루프를 수행합니다.
- KMP/CMP에서는 공통 코드와 플랫폼 경계, Android·iOS 검증을 함께 확인합니다.

## 설치 결과

`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`에 같은 짧은 진입 지침을 추가합니다.
공통 규칙과 MIT 라이선스는 `.harness/ux-loop/`에 설치합니다.
OpenDock 관리 블록 밖의 기존 내용은 보존됩니다. 개인·팀 정책은 관리 블록 밖에 유지하세요.
에이전트가 이 지침 파일을 읽도록 설정된 환경에서 사용하거나, 작업 요청에서
`.harness/ux-loop/README.md`를 명시적으로 읽도록 지정하세요.

실행 파일, SDK, 런타임 요구사항, 설치 작업, 외부 서비스 연결은 없습니다.
프로젝트의 빌드 파일, 소스, 테스트, CI 설정을 설치 시 변경하지 않습니다.
규칙만 설치되므로 실제 검증 도구를 자동으로 제공하거나 통과를 보장하지 않습니다.

## 사용 예

> 이 프로젝트의 기존 구조를 유지하고 UX Loop Harness 규칙을 적용해 이 디자인을 구현해줘.
> 실행 가능한 검사로 검증하고 실행하지 못한 항목은 근거와 함께 구분해줘.

디자인이 없는 로직 작업에서는 시각 검사를 억지로 추가하지 않습니다.
프로젝트에 없는 결제 기능, 플랫폼, 프레임워크를 도입하지 않습니다.
기존 승인과 팀 관례를 따르며, 사용자 요청 없이 브랜치 변경·배포·외부 게시를 강제하지 않습니다.

## 관리

Hub에서 승인된 릴리스의 `owner/ux-loop@version` 참조로 설치합니다.
`opendock doctor`, `opendock update`, `opendock uninstall owner/ux-loop`로 관리할 수 있습니다.
Doctor는 설치 상태 점검이며 앱의 UX 검증 결과가 아닙니다. 로컬 수정 충돌 시 내용을 검토해 해결하세요.
